ROOT CAUSE (proven, evidence in kdata_probe run):
- Probe `kdata_probe.slang` reads the blob 3 ways in one dispatch:
    (a) inline typed dynamic index : params->data.words[i]      -> MISCOMPILED
    (b) raw dynamic index          : params_raw[i]              -> CORRECT (== host, all 640)
    (c) base-ptr dynamic index     : (&params->data.words[0])[i]-> CORRECT (== host, all 640)
  plus a CONSTANT-index read params->data.words[356] -> CORRECT (0x0 == host).
- Host compares each vs host_kernel_data() (= host_params_.data, the blob const_copy_to uploaded).
- Result (instance2.xml): typed-vs-host=639, raw-vs-host=0, baseptr-vs-host=0, unwritten=0.
  View (a) returns 0x80000803 for EVERY i (incl. i=0). 0x80000803 is NOT a probe sentinel (prefill
  was 0xA5A5A5A5, unwritten=0); it is the REAL kernel_features (blob word 0) — the ABI probe logs
  literal `data.words[0]=0x80000803` too. => The inline `params->data.words[<dyn i>]` expression
  DROPS the dynamic index and always loads words[0]. Constant index and base-pointer index both
  work, so the struct layout (data@0, words@0-in-data, stride 4) is byte-correct.
- offsetof(KernelData,bvh)=1424, offsetof(KernelBVH,root)=0 => bvh.root at word 356 (confirmed live).
- CAUTION: traverse_probe.slang:104-115 comment MIS-attributes this to "a stride that does not
  match". That is WRONG — the stride/layout is correct; it is a dynamic-index codegen bug. The
  traverse probe's raw-view workaround is nonetheless the CORRECT pattern. Left the comment as-is
  (out of S1b-0 scope: no layout fix was found, and the task scoped frozen edits to a layout fix).

FIX / RULE FOR ALL FUTURE SLANG: never dynamically index `params->data.words[]` inline. Take the
base pointer once (`uint* base = &params->data.words[0];`) and index through it, or use the raw
`uint*` view — both are proven correct. (No code change was required; traverse.slang already uses
the raw view.)
