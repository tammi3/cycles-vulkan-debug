WHY SKIPPING THE RESTORE IS BENIGN HERE (code citations, run-9 traverse.slang)
------------------------------------------------------------------------------
The pop block (:445-455) writes back 6 things. Only ONE can ever matter:
  tmin/tmax (:452-453): DEAD CODE. grep confirms tmin=/tmax= appear ONLY
      at :452-453 (and the orig_ saves at :230-231). Nothing in the loop
      ever changes them, so restoring them is always a no-op.
  dir/idir  (:447-451): DEAD for this scene. dir is only written by the
      instance push (:416-419). All four itfm are pure TRANSLATIONS
      (identity rotation - dump-confirmed), so transform_direction leaves
      dir unchanged -> the restore writes back the same bits.
  current_object (:454): DEAD at the top level. It is only READ at :336
      (pobj pick) inside a GEOMETRY leaf. The top level here has ONLY
      instance leaves (leaves 0-3); the geometry leaves (4-6) live inside
      the object BVHs. After a pop the next top-level thing is an inner
      node or an instance leaf, and the instance push (:425) overwrites
      current_object before any geometry leaf can read it.
  P         (:446): the ONLY live restore. It matters ONLY IF another
      top-level node is tested after the pop AND the untranslated P flips
      that node's AABB verdict (:268-283).

For 12829+3542 = 16371 rays (0 or 1 instance) no node is tested after the
pop: the object BVH unwinds to the sentinel and the do/while at :465 exits.
The restore is never observed -> zero effect by construction.

For the 13 two-instance rays a node IS tested after the pop, yet the effect
is still 0. The reason is scene-specific: obj0 (the CENTRE cube, nearest to
the camera) has an IDENTITY itfm, so its object space == world space and
its pop is a bit-exact no-op. obj0 is the nearest child at top-level node 0
(camera (0,-6,3), obj0 at origin dist 6.7 vs 7.5 for the side cubes), so it
is always visited FIRST. The 13 two-instance rays therefore enter obj0 first
(pop = no-op) and then a side cube; when that side cube is popped, the next
node test happens to miss with the untranslated P too. Measured: 0 pixels.

SO: the fault is structurally unobservable on PURE-TRANSLATION, non-
OVERLAPPING instances. To make the pop observable the scene needs a
NON-IDENTITY rotation or scale in some itfm (so dir/idir really change
during the push) and/or overlapping instances along a ray (so a translated
instance's pop is followed by a P-sensitive node test). NOT created here.
