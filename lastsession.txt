ROOT CAUSE (probes v1-v6, all on RX 570, amdvlk 31.0.21925.1001):
the driver sizes the OpLoad of a POINTER-TYPED struct member by the POINTEE
element width instead of 8 bytes:
  uint32_t* member -> 4-byte load -> CORRECT (every device address on this
                      4 GB card is < 4 GB, e.g. base 0x18580000)
  uint16_t* member -> 2-byte load -> TRUNCATED (v5: shadow_path.queued_kernel
                      member holds 0x18581240, the load yields 0x1240)
  uint8_t*  member -> 1-byte load -> TRUNCATED (v4: path.mnee holds
                      0x18580128, the load yields 0x28)
So path.bounce (uint16_t*, true value 0x18580060) loads as 0x60 -> the
accessor addresses near physical page 0 -> reads return 0 (v2), writes vanish
(v3 got=eeee), and the gate's NARROW mode 0 fails with exactly the 8 sub-word
slices x 8 states = 64 mismatches. NOT a port bug: spirv-val passes and the
narrow accessors are byte-identical in shape to default mode. Default
(word-view, uint32_t*) mode works because its pointer loads are 4 bytes =
full for this card; Stage A narrow probes work because their pointers come
from PUSH CONSTANTS, not struct-member loads; SwiftShader cannot run narrow
at all (no shaderInt16/Int8 -> VUID + UNSUPPORTED capability 22/39).
