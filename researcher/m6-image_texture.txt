6. Hazards for Slang (FACT unless marked)
1. uint64→pointer casts: const TexT *data = (const TexT *)info.data; (cpu/image.h:166,180,291); (ccl_gpu_image_object_2D)info.data (gpu/image.h:64). In Slang: BDA uint64 → typed base pointer.
2. 8-bit loads (BYTE4 = the common PNG case): reading uchar/uchar4 from a PhysicalStorageBuffer needs Int8 on RX 570; SwiftShader has neither Int8 nor Int16 (FACT from lastsession.txt STAGE A ITEM 1: "RX 570: shaderInt16=1 ... shaderInt8=1; SwiftShader: all 0"). Portable repo pattern = word loads + mask/shift (src/kernel/device/vulkan/subword_word.slang header, pasted: "This file uses ONLY uint32 ... no Int16/Int8 capability"). For read-only pixels: load one uint (4 RGBA8888 bytes) per texel — no atomics needed.
3. DEVICE RULE (dynamic indexing): RX 570 miscompiles dynamic indexing on fixed array members behind BDA structs (AGENTS.md). The image code indexes kernel_data_fetch(image_info, dynamic) and image_textures[dynamic] (gpu/image.h:105,128; cpu/image.h:344,353) — in Slang always go through a raw base pointer (params.image_info[i] as uint64*), never a fixed-array member.
4. Templates/C++: ImageInterpolator is a template with if constexpr (std::is_same_v<...>) (cpu/image.h:37-47); port as an explicit switch(data_type). kernel_image_interp_bicubic is a ccl_device_noinline template (gpu/image.h:60-61).
5. half loads: half_to_float_image/half4_to_float4_image (src/util/half.h:289,294). Whether Float16-typed pointers are accepted on PhysicalStorageBuffer by the validation layer on both devices is UNVERIFIED; safe fallback = load uint/uint64 bits and decode manually.
6. Function pointers: only host-side (types_image.h:193-195, guarded #ifndef __KERNEL_GPU__, pasted). No shader hazard.
7. No recursion/dynamic allocation in the sampler (fixed 4×4 cubic loop, cpu/image.h:271-310). Don't port the CPU load-request callback.
8. Full-resident sampling is read-only over image_info + pixels (FACT) — fits our BDA discipline.
9. Y orientation: OIIO loads flipped (oiio_load_pixels(..., flip_y = true) default, src/util/image_metadata.h:77); CPU full path samples xy = uv * (w,h) without further flip (cpu/image.h:365), tiled path flips (image_2d.h:128). Match the CPU full-path convention or the gate image is vertically mirrored (negative-test candidate).

9. Options and decision points
USER DECISION 1 — Tile cache in M6 v1?
(a) Fully resident only (RECOMMENDED): no tile protocol, no abort/retry, no access-state readback, no eviction; covers every v1 gate; images without a .tx sibling always take this path. (b) Include tile cache: only needed to match Blender production .tx/UDIM flows; much larger cost (kernel protocol + host retry loop + eviction + per-tile OIIO loading) and it touches integrator scheduling. The fork's clean split at image.cpp:493 means (b) can be added later without redesign.
USER DECISION 2 — Interpolation modes in v1?
linear + closest (RECOMMENDED, ~200 lines, covers the default and the deterministic reference); + cubic/smart later (~120 lines; if added, port the CPU SET_CUBIC_SPLINE_WEIGHTS form for faithfulness, not the GPU bicubic).
USER DECISION 3 — Formats in v1?
byte4 + float4 minimum (RECOMMENDED: PNG/JPEG + float EXR); add half4 if any EXR is in scope; ushort/1-channel last (rare). Only tricky part is fp16 decode without Int16/Float16 features — decode from 32-bit words to stay portable.
UNVERIFIED ASSUMPTIONS
1. KernelImageInfo.data = BDA of the pixel buffer for Vulkan is an INFERENCE from the CPU design; no Vulkan code does it yet (NOT FOUND in src/device/vulkan/).
2. Word-load RGBA8888 (one uint per texel) assumes tightly packed 4-byte rows from OIIO through conform_pixels (image_metadata.cpp:503-533 strongly implies it); row stride/alignment not verified pixel-by-pixel — T2 probe must confirm.
3. SwiftShader cannot run fp16/Int16/Int8 BDA loads (from lastsession.txt device facts) → HALF/USHORT probes would be RX 570-only unless decoded from 32-bit words — T4 must measure.
4. The proposed plane_texture.xml axis orientation was NOT rendered; render on CPU first.
5. The 2 GB cap / 4 GB VRAM are design constraints given in the task brief; no code constant found (grep for 2 GB / 0x80000000 in src/device/vulkan/device.cpp → no output).
