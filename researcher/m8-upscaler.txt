b) Where FSR1 pass hooks in: buffer layouts + RenderBuffers
Pipeline order (corrected from notes)
PathTrace (low-res: width/scale × height/scale)
    │
    ▼
RenderBuffers (low-res) — contains: COMBINED, ALBEDO, NORMAL, DEPTH, MOTION
    │
    ▼
[NEW] VulkanUpscaler (Slang compute)
    │   Input:  low-res COMBINED + NORMAL + DEPTH (+ MOTION if temporal)
    │   Output: high-res COMBINED (full resolution)
    │
    ▼
RenderBuffers (high-res) — COMBINED now at full res
    │
    ▼
Denoiser (OIDN CPU) — runs on high-res COMBINED + ALBEDO + NORMAL
    │
    ▼
Film convert/display — saves final image
RenderBuffers multi-resolution support (source: intern/cycles/render/buffers.h:200-300)
FACT: RenderBuffers holds one resolution per instance (BufferParams width/height). To support upscaling:
- Option A: Two RenderBuffers instances — low-res (path trace) + high-res (upscale output)
- Option B: Single RenderBuffers with full_width/full_height ≠ width/height (already exists for denoiser)
FACT: BufferParams already has:
int width, height;           // actual buffer resolution
int full_width, full_height; // target resolution (for denoiser/upscale)
int pass_stride;             // floats per pixel
FACT: film_convert() (source: film/write.h) reads full_width/full_height for output scaling.
Required changes:
1. RenderScheduler: allocate low-res RenderBuffers for path trace (width = full_width/scale)
2. VulkanUpscaler: takes low-res RenderBuffers, writes to high-res RenderBuffers (separate instance or same with full_width)
3. Denoiser: runs on high-res buffers (already supports full_width)
4. Session: coordinate buffer swap between path trace → upscaler → denoiser

Plain-language spec
EASU (Edge Adaptive Spatial Upsampling) — 2× upscale
1. Input: low-res color (RGB), optional depth/normal for edge detection
2. For each output pixel (2×2 grid per input pixel):
- Compute 5×5 input neighborhood
- Edge detection: luminance gradient + depth/normal discontinuity
- Directional weights: 4 directional gradients (N, S, E, W) → weight = 1/(1+gradient)
- Accumulate: weighted sum of 12 nearest input pixels (3×4 pattern)
- Sharpening: optional contrast adaptive sharpening (CAS) blend
3. Output: 2× resolution color
RCAS (Robust Contrast Adaptive Sharpening) — post-process
1. Input: upscaled color (from EASU or any source)
2. For each pixel: 3×3 neighborhood
3. Local contrast: max - min in 3×3
4. Sharpening weight: saturate(contrast * sharpness_factor)
5. Filter: 5-tap sharpening kernel (center + 4 diagonals) weighted by local contrast
6. Output: sharpened color

UNVERIFIED ASSUMPTIONS (M8)
1. FSR1 license — MIT confirmed from AMD repo; safe to bundle
2. RenderBuffers dual-resolution — need to verify full_width/height usage in film_convert and denoiser
3. NCNN VkDevice sharing — can NCNN wrap Cycles' VkDevice/VkQueue? (Check ncnn::VulkanDevice constructor)
4. Motion vector pass for temporal — PASS_DENOISING_BACKWARD_MOTION exists; FSR1 doesn't use it natively; would need custom temporal pass
5. Alpha channel handling — FSR1 operates on RGB; alpha must be upscaled separately (nearest neighbor)
6. HDR support — FSR1 expects linear RGB; works for HDR if tone-mapped after
7. Sharpness parameter — expose in UI (0.0–1.0), default 0.5
